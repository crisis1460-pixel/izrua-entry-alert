DB 커밋은 유실될 수 있으므로, 커밋이 날아가면 **다음 회차가 같은 알림을 다시 보낸다.**

정황도 일치한다 — 직전에 회차 커밋이 18:47:38 → 18:53:31 로 **약 6분 비었고**(2분

GitHub Actions 로그는 이 환경에 `gh` 가 없어 직접 확인하지 못했다.

> 참고: 워크플로 주석(175~179행)에 이미 "concurrency 가 직렬화한다는 전제를 실측이

`collector/tradingview.py:79` 의 `_blocked_until` 은 **모듈 전역 변수**다. 회차마다
새 프로세스라 매번 0 으로 리셋되고, DB `meta` 에도 영속화되지 않는다(실측: meta 에

문구가 틀렸고 "재시도는 밴을 키울 뿐"이라는 코드 자체의 판단과도 어긋난다.
