## A. 측정/분석 고도화 (데이터 기반 의사결정 지원)

현재 축적 중인 데이터를 더 세밀하게 분석하여, 향후 채점·게이트 조정의 근거를 마련하는 항목.

### A-1. 등급 내 점수 구간별 적중률 세분화

**현재**: `get_grade_stats()`가 등급(S/A/B/C/D) 단위로만 wins/losses 집계.  
**제안**: 점수 5점 단위 버킷(40-44, 45-49, ..., 85-89, 90+)별 적중률 추가 산출.  
**이유**: 등급 경계 최적화 근거. 예) B등급(55-69) 내에서 55-59 vs 65-69의 적중률 차이가 크면, B를 분할하거나 경계를 이동하는 결정을 데이터로 뒷받침.  
**구현 난이도**: 낮음 — `get_grade_stats()` SQL에 `score` 버킷 GROUP BY 추가. 주간 오디트 JSON에 포함.

### A-2. 채점 요소별 기여도 분석 (attribution)

**현재**: 각 요소(팔로워·근접도·목표거리·완결성·실적)의 배점은 알지만, 실제 적중률에 대한 기여도는 미측정.  
**제안**: 주간 오디트에서 종결 레벨들의 요소별 점수를 분해 기록 → 각 요소의 적중률 상관계수 산출.  
**이유**: "팔로워 25점을 받은 레벨의 적중률"과 "팔로워 1점 레벨의 적중률" 차이가 실측으로 나오면, 팔로워 배점의 타당성을 검증·보정 가능.  
**구현 난이도**: 중간 — 종결 레벨에 요소별 점수 분해 저장 필요 (현재 총점만 저장).

### A-3. ret_24h/ret_72h 등급별 분포 분석

**현재**: `ret_24h`, `ret_72h` 수집 중이지만 등급별 분석 미수행.  
**제안**: 주간 오디트에 등급별 평균/중앙값/표준편차 추가.  
**이유**: "S등급 신호의 24h 평균 수익률이 C등급보다 실제로 높은가?" → 등급 시스템의 실효성(순위 변별력) 검증. 적중률이 같아도 수익률 분포가 다르면 등급의 가치가 다름.  
**구현 난이도**: 낮음 — 기존 ret 칼럼 + grade 조인.

### A-4. 터치 소요시간과 적중률 교차 분석

**현재**: `_compute_touch_time_stats()`가 시간 버킷별 적중률을 산출하지만 등급과 교차하지 않음.  
**제안**: (등급 × 시간버킷) 2차원 적중률 매트릭스.  
**이유**: "S등급이면서 1시간 내 터치된 신호"의 적중률이 특별히 높다면, 향후 속도 가점이나 별도 표기의 근거.  
**구현 난이도**: 낮음 — 기존 쿼리에 grade 칼럼 추가.

### A-5. 시장 심리 지표-적중률 상관관계

**현재**: F&G, BTC.D, ALT.S, 김프 등이 알림에 표시되지만 적중률과의 상관관계는 미분석.  
**제안**: touch_fear_greed, touch_btc_dominance 등 터치 시점 스냅샷과 outcome의 상관계수 산출 (주간 오디트).  
**이유**: "F&G 20 이하에서 터치된 long 신호의 적중률이 70%+"라면, 시장 조건 기반 가중치의 근거.  
**구현 난이도**: 중간 — touch_* 칼럼 충분히 쌓인 후(~50건+) 의미 있음.

## B. 채점 시스템 고도화 후보

데이터가 충분히 축적된 후 적용 가능한 채점 개선 항목.

### B-1. 작성자 실적 가점 연속 함수화

**현재**: Wilson 80% 하한 기준 3단계 계단(0.55→+15, 0.40→+10, 0.25→+5).  
**후보**: `floor(wilson_lo × 25)` 같은 연속 함수로 전환 → 0.55와 0.54 사이의 불연속 해소.  
**전제조건**: 충분한 종결 표본(작성자별 20건+)에서 계단 구간 내 분포가 균일한지 확인.  
**위험**: 연속 함수는 소표본 노이즈에 더 민감 — 현재 계단 구조가 소표본 안전성에서 우월. 급할 이유 없음.

### B-2. Profit Factor / R-Expectancy 기반 작성자 가점

**현재**: 작성자 실적 가점이 적중률(Wilson 하한)만 반영. `get_author_advanced_stats()`의 PF·R-Exp는 미사용.  
**후보**: Wilson 하한 + PF 조합 점수 → 적중률은 비슷하지만 R이 큰 작성자에 추가 가점.  
**전제조건**: PF와 적중률의 독립적 예측력 확인 (높은 상관이면 중복 가점).  
**위험**: R-Exp는 SL 존재 여부에 크게 의존 → SL 없는 글이 54%인 현황에서 편향 위험.

### B-3. 클러스터 대표 선정 고도화

**현재**: `_rep(cluster, current_usd)` — 재채점 점수 최대 멤버. 동점 시 리스트 순서(id순) 의존.  
**후보**: 명시적 tiebreaker 추가 — (1) 작성자 실적 가점이 높은 쪽, (2) 글 나이가 더 최신, (3) TP 거리가 5~15% 범위(최적) 내인 쪽.  
**구현 난이도**: 낮음 — `_rep()` 내 key 함수에 2차·3차 정렬 기준 추가.  
**위험**: 거의 없음 (현재 동작과 동점일 때만 차이).

### B-4. 방향성(Direction) 게이트

**현재**: 시장 전체 방향과 무관하게 long 신호만 처리.  
**후보**: BTC 추세 또는 ALT.S가 극단적 하락세(F&G < 15 또는 BTC.D 급등)일 때 알림 빈도를 자동 감소시키는 가중치.  
**전제조건**: 시장 조건별 적중률 데이터(A-5) 축적 후 결정.  
**위험**: 과적합 — 시장 조건은 항상 변하므로, 고정 규칙이 미래에도 유효할지 불확실.

## C. 코드 레벨 개선 (동작 변경 없음)

### C-1. Short 방향 판정 미지원 명시화

**현재**: `_judge_outcomes()`의 TP/SL 판정(`c_high >= tp_krw`, `c_low <= sl_krw`)과 오염 방어선(`if direction == "long"`)이 long 전용. `_tps_valid`도 `if direction == "long" else []`. 터치 판정(`_eff_low <= top_krw`)도 long 전용.  
**현황**: 파이프라인 전체가 long-only로 설계됨 (의도적). TV long 아이디어가 절대 다수.  
**제안**: 코드 상단에 short 미지원을 명시하는 주석 + `direction != "long"` 레벨의 판정 스킵 로직 추가(현재는 short 레벨이 long 로직으로 판정되어 오결과 가능).  
**구현 난이도**: 낮음.

### C-2. 채점 요소 분해 저장

**현재**: `calculate_grade()` 반환값이 `(grade, score, rr)` — 총점만 저장.  
**제안**: 반환 dict에 `{"follower_pts": ..., "proximity_pts": ..., "tp_dist_pts": ..., "data_pts": ..., "author_pts": ...}` 분해 추가. levels 테이블에 새 칼럼 또는 JSON 칼럼으로 저장.  
**이유**: A-2 분석의 전제조건. 현재는 사후 역산이 불가능(총점에서 역으로 요소를 추출하려면 모든 입력을 다시 읽어야 함).

### C-3. 가격 근접도 10%+ 위 구간 명시화

**현재**: `diff_pct >= 10` (현재가가 entry 대비 10% 이상 위)일 때 근접도 0점 — 어떤 if/elif에도 안 걸려 "무시"됨.  
**제안**: 명시적 `else: score += 0` 또는 코멘트로 의도 명확화. 작은 개선이지만 코드 가독성 향상.

## D. 현시점 권장 우선순위

| 순위 | 항목 | 이유 |
|------|------|------|
| 1 | A-1 점수 구간별 적중률 | 구현 쉽고 v4 경계 검증에 즉시 유용 |
| 2 | A-3 ret_24h/72h 등급별 분포 | 구현 쉽고 등급 실효성 최초 측정 |
| 3 | C-2 채점 요소 분해 저장 | A-2의 전제, 한번 넣으면 이후 모든 분석 가능 |

| 5 | C-1 short 미지원 명시화 | 코드 안전성 (오판정 방지) |
| 6 | B-3 대표 선정 tiebreaker | 낮은 위험, 낮은 노력 |
| 후순위 | A-2, A-5, B-1, B-2, B-4 | 데이터 축적 필요 또는 위험도 높음 |
